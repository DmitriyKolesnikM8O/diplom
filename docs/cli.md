# CLI `peaudit`

> Справочник по командам и флагам. Контракт отчёта описан отдельно —
> [`report-schema.md`](report-schema.md); архитектурные решения — в
> [`adr/`](adr/).

```
peaudit scan <FILE> [--json|--jsonl] [--pretty] [--profile ...] [--strict]
                    [--fail-on ...] [--min-severity ...] [--output FILE]
                    [--hashes ...] [--no-hashes] [--limit KEY=VALUE]...
peaudit batch <DIR> [--recursive] [--jobs N] [--jsonl] [--all-files]
                    [--output FILE]
                    [--profile ...] [--fail-on ...] [--strict]
                    [--hashes ...] [--no-hashes] [--limit KEY=VALUE]...
peaudit rules list [--json]
peaudit rules explain <ID>
peaudit schema [--output FILE]
peaudit version
```

`FILE` — путь или `-` для stdin. `peaudit --help` и `peaudit <command> --help`
печатают ту же грамматику.

## `scan`

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--json` | выкл. | Полный отчёт одним JSON-документом |
| `--jsonl` | выкл. | Тот же отчёт одной строкой (формат `batch`) |
| `--pretty` | выкл. | Отступы в JSON; требует `--json` |
| `--profile spec\|loader\|security` | `security` | Профиль, по которому считается гейт и строка `gate:` |
| `--fail-on info\|low\|medium\|high\|critical\|never` | `high` | Порог гейта по severity находки |
| `--min-severity ...` | `info` | Скрыть находки ниже порога **в человекочитаемом выводе** |
| `--output FILE` | stdout | Записать вывод в файл (`-` = stdout) |
| `--hashes sha256\|all` | `sha256` | Какие дайджесты считать |
| `--no-hashes` | выкл. | Не считать дайджесты вовсе |
| `--strict` | выкл. | Любая диагностика уровня `error` — отказ (код 1) |
| `--limit KEY=VALUE` | — | Переопределить safety-лимит (можно несколько раз) |

`--json` и `--jsonl` взаимоисключающие; `--hashes` и `--no-hashes` тоже.

## `batch`

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--recursive` | выкл. | Обходить подкаталоги |
| `--jobs N` | `0` (все CPU) | Число потоков, максимум 32 |
| `--jsonl` | выкл. | Один отчёт на строку вместо сводки |
| `--all-files` | выкл. | Брать все файлы, а не только PE-расширения |
| `--output FILE` | stdout | Записать вывод в файл (`-` = stdout) |
| `--profile`, `--fail-on`, `--strict`, `--hashes`, `--no-hashes`, `--limit` | как у `scan` | — |

Без `--all-files` сканируются файлы с расширениями `exe`, `dll`, `sys`, `ocx`,
`cpl`, `scr` (регистр не важен). Порядок вывода — лексикографический порядок
путей, независимо от числа потоков.

Симлинки и Windows junction'ы не обходятся: `DirEntry::file_type` не следует по
ссылкам, поэтому цикл через junction (например, `AppData\Local\Application Data`)
невозможен. Отчёты собираются в память и печатаются после обхода, чтобы порядок
был детерминированным; на очень больших каталогах это стоит помнить.

Человекочитаемый режим печатает строку на файл и итог:

```
C:\samples\clean.exe: security 0 (clean), findings 0
C:\samples\dirty.dll: security 10 (low), findings 1
analyzed: 2, with findings: 1, errors: 0
worst: spec 0 (clean), loader 0 (clean), security 10 (low)
```

В `--jsonl` каждая строка — самостоятельный отчёт по схеме, итоговая сводка не
печатается. Файл, который не удалось прочитать, отчёта не имеет: сообщение
уходит в stderr, код возврата становится `2`, остальные файлы обрабатываются.
Битый PE — не ошибка: он даёт отчёт с `parse.status` `failed` или `partial`.

## `rules`

`rules list` печатает таблицу `ID / SEVERITY / CONF / PROFILES / TITLE`;
`rules list --json` — массив объектов с полным `RuleMeta` (`id`, `title`,
`description`, `severity`, `confidence`, `category`, `profiles`, `references`,
`since`). `rules explain <ID>` печатает одно правило целиком; неизвестный ID —
ошибка использования (код 2). Источник данных — тот же реестр, из которого
генерируется [`rules.md`](rules.md), поэтому CLI и документация не расходятся.

## `schema` и `version`

`schema` печатает `docs/report.schema.json`, вкомпилированный в бинарник: это
ровно та схема, против которой проверяются отчёты в тестах. `--output FILE`
пишет её в файл.

`version` печатает версию инструмента и версию схемы отчёта, например
`peaudit 0.1.0 (report schema 1.0)`.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | нет находок на уровне `--fail-on` и выше |
| 1 | есть находки на уровне `--fail-on` и выше, либо `--strict` отверг файл |
| 2 | ошибка аргументов или ввода-вывода |
| 3 | внутренняя ошибка (баг) |

В `batch` код `2` имеет приоритет: если хотя бы один файл не удалось прочитать,
это ошибка ввода-вывода, даже когда у других файлов есть находки.

## Профили и гейт

Три профиля — это три разных вопроса к одному файлу, а не уровни строгости
([ADR-0004](adr/0004-three-profiles.md)). Отчёт всегда содержит все три
вердикта; `--profile` выбирает только тот, по которому считается код возврата и
строка `gate:`. Гейт сравнивает **severity отдельной находки**, а не score:
порог `high` означает «есть находка `high` или `critical` в этом профиле».
Поэтому калибровка весов на код возврата не влияет.

## `--strict`

`--strict` возвращает код 1, если парсер оставил хотя бы одну диагностику
уровня `error` — то есть ему пришлось остановиться раньше или пропустить
структуру ([ADR-0003](adr/0003-partial-parsing.md)). Разбор при этом не
прерывается: partial parsing — режим по умолчанию, и отчёт всё равно печатается.
В режиме `--json`/`--jsonl` отказ виден только по коду возврата: документ
остаётся обычным отчётом. Флаг предназначен для проверки самого парсера и для
CI, а не для анализа образцов.

## Ввод и лимиты

Размер файла проверяется по метаданным **до** чтения; stdin читается через
`Read::take(max + 1)`, поэтому слишком большой поток отвергается, не занимая
память целиком. Значения по умолчанию:

| Ключ `--limit` | По умолчанию |
|---|---|
| `max-file-size` | 536870912 (512 МиБ) |
| `max-sections` | 4096 |
| `max-imports` | 65536 |
| `max-exports` | 65536 |
| `max-resource-nodes` | 65536 |
| `max-resource-depth` | 32 |
| `max-string-len` | 4096 |
| `max-thunks-per-import` | 65536 |
| `max-entropy-window` | 4096 |

Это потолки объёма работы, а не пороги спецификации: файл с 100 секциями
нарушает спецификацию, но разбирается (нарушение сообщит `PE-COFF-001`).

## Пример для CI

```yaml
- name: Analyze the build output
  run: peaudit batch ./target/release --jsonl --output reports.jsonl
  # код 1 остановит job, если найдена находка high и выше в профиле security
```

Чтобы отделить «файл не читается» от «файл подозрительный», проверяйте код
возврата: `2` — проблема окружения, `1` — результат анализа.
