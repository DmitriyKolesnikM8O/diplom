# Бенчмарк хэшей: цена одного и трёх проходов

- **Дата:** 2026-11-22
- **Фаза:** 2 (фундамент ядра), итерация B
- **Платформа:** Windows 11, Rust 1.99.1, профиль `release` (`lto = "thin"`)

## Что измерялось

Каждый хэш — это полный проход по входному буферу. Измерялись отдельные
алгоритмы и две политики целиком на буфере 10 МиБ псевдослучайных байт
(xorshift64):

- `HashSelection::SHA256_ONLY` — политика по умолчанию;
- `HashSelection::ALL` — SHA-256 + SHA-1 + MD5, три прохода.

Метод — ignored-тест, чтобы бенчмарк не замедлял обычный прогон:

```powershell
cargo test -p peaudit-core --release bench_hashes_10mb -- --ignored --nocapture
```

## Результат

| Алгоритм / политика | Время | Пропускная способность |
|---|---|---|
| SHA-256 | 10.3 мс | 972 МиБ/с |
| SHA-1 | 9.4 мс | 1067 МиБ/с |
| MD5 | 29.6 мс | 338 МиБ/с |
| SHA-256 (политика по умолчанию) | 8.6 мс | 1157 МиБ/с |
| Все три (3 прохода) | 47.2 мс | 635 МиБ/с |

## Вывод и решение

- Один проход SHA-256 стоит ≈ 9–10 мс на 10 МиБ; три прохода — ≈ 47 мс, то есть
  **в 5.5 раза дороже** при том, что SHA-1 и MD5 нужны только для сверки с
  внешними базами.
- Поэтому по умолчанию считается **только SHA-256** (`HashSelection::SHA256_ONLY`),
  а все три — по явному запросу: `peaudit <file> --hashes all`.
- SHA-1 и MD5 остаются в коде: многие фиды публикуют именно их, и отказ от них
  сломал бы сверку. Криптостойкость здесь не важна — хэши не используются ни в
  одном решении анализатора.
- MD5 — самый медленный из трёх (338 МиБ/с), хотя исторически считается
  «дешёвым»; это ещё один аргумент не считать его по умолчанию.

## Ограничения

- Синтетические данные; скорость хэшей от содержимого не зависит.
- Один прогон без прогрева и статистики; `criterion` появится на фазе 12.
- Учитывается только хэширование, без чтения файла и разбора PE.
