# Бенчмарк энтропии: базовое число

- **Дата:** 2026-11-22
- **Фаза:** 2 (фундамент ядра)
- **Коммит:** рабочее дерево, фаза 2
- **Платформа:** Windows 11, Rust 1.99.1, профиль `release` (`lto = "thin"`)

## Что измерялось

`EntropyProfile::compute(data, 4096, 7.0)` на буфере 10 МиБ псевдослучайных
байт (xorshift64*): общая энтропия плюс скользящее окно 4096 байт с шагом 1.

Метод — ignored-тест, чтобы бенчмарк не замедлял обычный прогон:

```powershell
cargo test -p peaudit-core --release bench_entropy_10mb -- --ignored --nocapture
```

## Результат

| Метрика | Значение |
|---|---|
| Время | 158.9 мс |
| Пропускная способность | 62.9 МиБ/с |
| Оценено окон | 10 481 665 |
| Общая энтропия | 8.0000 |

## Что дало ускорение

Первая версия вызывала `log2` четыре раза на каждый шаг окна (добавление и
удаление байта, по два вызова каждое): **1309 мс, 7.6 МиБ/с**.

Замена на таблицы `c·log₂c` и `log₂n`, построенные один раз на профиль,
убрала логарифмы из горячего цикла: **159 мс, 62.9 МиБ/с**, ускорение ≈ 8×.
Таблицы занимают 16 байт на элемент окна (64 КиБ для окна 4096); для окон
больше 65 536 байт используется прямой расчёт, чтобы не выделять гигантский
массив.

## Ограничения

- Синтетические данные: на реальных PE-файлах распределение байт иное, но
  стоимость алгоритма от данных не зависит.
- Один прогон без прогрева и без статистики; `criterion` появится на фазе 12,
  когда понадобятся сравнимые между версиями числа.
- Учитывается только вычисление энтропии, без чтения файла и хэширования.
