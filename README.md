# peaudit

[![CI](https://github.com/DmitriyKolesnikM8O/diplom/actions/workflows/ci.yml/badge.svg)](https://github.com/DmitriyKolesnikM8O/diplom/actions/workflows/ci.yml)
[![License: MIT OR Apache-2.0](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](#лицензия)

**Открытый инструмент статического анализа PE-файлов.** Устойчивый к враждебному
входу парсер, структурные проверки, три независимых вердикта и машиночитаемый отчёт.

`peaudit` создаётся как **экспресс-анализатор структуры**, а не антивирус: он не
дизассемблирует код, не эмулирует его и не запускает исследуемый файл. Задача —
быстро и объяснимо показать, что не так с PE-файлом, насколько он соответствует
спецификации и как на него может отреагировать загрузчик Windows.

## Что он делает

- **Разбирает PE настолько глубоко, насколько возможно.** Ошибка в одном заголовке
  не обрывает анализ: она становится диагностикой, разбор продолжается (partial parsing).
- **Не падает и не зависает на повреждённых файлах.** Zero-copy чтение с проверкой
  границ, лимиты на секции, директории, импорты, ресурсы и глубину рекурсии.
- **Объясняет каждую находку.** Правило, поле, смещение, ожидаемое и фактическое
  значение, ссылка на спецификацию.
- **Даёт три независимых вердикта:**
  - `spec` — соответствие спецификации Microsoft PE/COFF;
  - `loader` — примет ли файл загрузчик Windows и не сломается ли он;
  - `security` — структурные аномалии и признаки сокрытия данных.
- **Работает как CLI и как библиотека.** JSON/JSONL для скриптов и CI/CD, C ABI для
  встраивания в сторонние приложения (DLL на Windows, `.so` на Linux).

Отдельный класс правил (`PE-LDR-*`) фиксирует **расхождение интерпретаций**
(parser differential): случаи, когда разные парсеры и загрузчик по-разному
понимают один и тот же деформированный файл.

## Статус

Готовы ядро и первая версия инструмента: безопасный `Reader`, парсер заголовков
PE/COFF с partial parsing, RVA-маппинг, checksum, энтропия, overlay, движок
правил с 15 правилами, отчёт со схемой v1.0 и CLI (`scan`, `batch`, `rules`,
`schema`). Следующие шаги — Rich Header, импорты/экспорты/ресурсы, расширение
каталога правил.

План работ и текущий прогресс — [`materials/roadmap.md`](materials/roadmap.md).
Каталог запланированных правил — [`materials/rules_catalog.md`](materials/rules_catalog.md).

## Быстрый старт

Требуется Rust (stable, edition 2024). Версия закреплена в `rust-toolchain.toml`.

```powershell
# все проверки: форматирование, clippy, тесты, документация
cargo xtask ci

# сборка
cargo build --workspace --release
```

## Использование

```powershell
# один файл: сводка, три вердикта, находки с полем и смещением
peaudit scan .\file.exe

# полный отчёт по схеме v1.0
peaudit scan .\file.exe --json --output report.json

# файл из stdin: `Get-Content -Raw` испортил бы двоичные данные
cmd /c "peaudit scan - --json < file.exe"

# каталог: один JSON-отчёт на строку, рекурсивно, в несколько потоков
peaudit batch .\samples --recursive --jsonl --output reports.jsonl

# каталог правил
peaudit rules list
peaudit rules explain PE-SEC-007

# JSON-схема отчёта
peaudit schema --output report.schema.json
```

> В PowerShell 5.1 оператор `>` пишет UTF-16, поэтому для JSON используйте
> `--output` (или `cmd /c`, если нужен именно редирект).

### Коды возврата

| Код | Значение |
|---|---|
| 0 | нет находок на уровне `--fail-on` и выше |
| 1 | есть находки на уровне `--fail-on` и выше (или `--strict` отверг файл) |
| 2 | ошибка аргументов или ввода-вывода |
| 3 | внутренняя ошибка |

По умолчанию гейт — `--fail-on high` по профилю `security`. Невалидный PE —
не ошибка: печатается отчёт, код зависит от находок.

### Форматы вывода

- без флагов — читаемая сводка;
- `--json` — полный отчёт по [`docs/report.schema.json`](docs/report.schema.json);
  `--pretty` добавляет отступы;
- `--jsonl` — тот же отчёт одной строкой, формат для `batch`.

`--min-severity` скрывает находки только в человекочитаемом выводе: JSON всегда
содержит все находки и все три вердикта. `--limit KEY=VALUE` переопределяет
safety-лимиты, например `--limit max-file-size=16777216`. Полный справочник —
[`docs/cli.md`](docs/cli.md).

## Структура репозитория

```
crates/peaudit-core/   парсер, модель, правила, отчёт (вся логика, без I/O)
crates/peaudit-cli/    CLI: аргументы, вывод, коды возврата
crates/peaudit-ffi/    C ABI: cdylib/staticlib для встраивания
xtask/                 служебные команды: ci, corpus, experiment, schema
docs/                  документация инструмента: архитектура, схема отчёта, правила
materials/             рабочие материалы ВКР: план, исследование, каталог правил
```

Зависимости направлены только внутрь: `cli` и `ffi` используют `core`, а `core`
не знает ни про файловую систему, ни про CLI, ни про FFI.

## Ограничения

Сознательно **вне scope**: дизассемблирование, эмуляция, распаковка, песочница,
ML-классификаторы, сетевые запросы, проверка подписи Authenticode (PKCS#7), GUI,
YARA-движок, лечение и карантин.

Инструмент не запускает исследуемые файлы и не является средством обнаружения
вредоносного ПО — он оценивает **структурный риск** и объясняет его.
